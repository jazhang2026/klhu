# Quickstart: App Icon Update

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-23

Validation guide. Every scenario names **how** it is proven. `[device]` runs on
the emulator, `[unit]` is a Dart test, `[structural]` is a file/APK check with no
app running. No implementation code here.

## Prerequisites

- Flutter SDK at `~/development/flutter` (`export PATH=$HOME/development/flutter/bin:$PATH`).
- Emulator `emulator-5554` (AVD `klhu`, API 36) attached.
- Android SDK build-tools 36.0.0 at `~/Android/Sdk/build-tools/36.0.0/aapt2`.
- `images/kalahoo.jpeg` present (1024×1024 JPEG).
- No macOS: the iOS half is structurally checked only (see scenario 6).

## Setup

```bash
cd /home/weihongzhang/Documents/GitHub/Projects/klhu
export PATH=$HOME/development/flutter/bin:$PATH
flutter pub get
dart run flutter_launcher_icons          # writes every asset in contracts/icon-assets.md
flutter build apk --debug
adb -s emulator-5554 install -r build/app/outputs/flutter-apk/app-debug.apk
```

## Automated checks

```bash
flutter analyze                          # clean
flutter test --concurrency=2             # includes test/app_icon_test.dart (scenario 2)
git status --short android/app/src/main/res ios/Runner/Assets.xcassets
```

The last line is the evidence that generation happened: it must list the
regenerated PNGs plus `res/values/colors.xml` and
`res/mipmap-anydpi-v26/ic_launcher.xml` (new files), and **nothing** under
`macos/`, `web/` or `windows/`.

## Validation scenarios

### 1. The launcher shows the custom icon — [device]

Prerequisites: app installed from the build in Setup; as a deliberate
"reinstall removes stale launcher cache" step, `adb shell pm clear com.example.klhu`.

Steps: `adb shell input keyevent KEYCODE_HOME`, wait for the launcher, then

```bash
adb -s emulator-5554 exec-out screencap -p > /tmp/launcher.png
unzip -p build/app/outputs/flutter-apk/app-debug.apk res/mipmap-xxhdpi/ic_launcher.png \
  | sha256sum
sha256sum android/app/src/main/res/mipmap-xxhdpi/ic_launcher.png
~/Android/Sdk/build-tools/36.0.0/aapt2 dump badging \
  build/app/outputs/flutter-apk/app-debug.apk | grep application-icon
```

Expected: the two hashes are identical (the APK carries the generated bytes);
`aapt2` lists `application-icon-<dpi>` entries for the mdpi…xxxhdpi mipmaps; the
screenshot shows the character art on white rather than the default Flutter logo.
Proven by: hash equality + the badging lines + the screenshot kept for human
review. An icon is pixels — the agent does not claim a visual match from a dump,
which is why the byte-level check carries the PASS and the screenshot corroborates
it.

### 2. Every density is present at its declared size — [unit]

Steps: `flutter test test/app_icon_test.dart`.

Expected: for each density the PNG exists and its pixel size equals 48/72/96/144/192;
each adaptive foreground is 108²; `mipmap-anydpi-v26/ic_launcher.xml` exists and
names `@color/ic_launcher_background` + an inset foreground; `values/colors.xml`
declares `#ffffff`. Proven by: the test's assertions against real files — the
contract between the config and its artifacts (`research.md` D8).

### 3. The adaptive icon is what Android 8+ draws — [device]

Steps: open Settings → Apps → klhu (or long-press the launcher entry) and capture
the screenshot; check the packaged descriptor:

```bash
unzip -l build/app/outputs/flutter-apk/app-debug.apk | grep -E "anydpi|ic_launcher_foreground|ic_launcher.png"
```

Expected: the APK contains `res/mipmap-anydpi-v26/ic_launcher.xml` and the
`drawable-*dpi/ic_launcher_foreground.png` layers; on screen the icon is masked by
the launcher's shape with the art fully visible (no clipped subject). Proven by:
the packaged file list + the screenshot (`contracts/icon-assets.md` C1–C3).

### 4. A stale launcher cache does not keep the old icon — [device]

Steps: with the previous build installed, install the new APK, then (a) relaunch
the launcher (`adb shell am force-stop com.google.android.apps.nexuslauncher` or a
device reboot), and compare with (b) `pm clear` + reinstall.

Expected: after (a) the icon is the new art; if a launcher still shows the old
bitmap, (b) proves it is cache, not assets — and that is the user-facing
guidance for this spec's edge case. Proven by: the same screenshot method as
scenario 1, before and after.

### 5. A missing source cannot break the build (FR-006) — [unit] + [build]

Steps:

```bash
mv images/kalahoo.jpeg /tmp/ && flutter build apk --debug ; mv /tmp/kalahoo.jpeg images/
dart run flutter_launcher_icons            # with the source absent
```

Expected: the **build succeeds** with the source absent (nothing in the build
reads it — `research.md` D5), and the generator **fails loudly** with a
non-zero exit and a file/decoder error rather than writing a partial asset set
or a placeholder icon. Proven by: the build's exit code and the generator's
error output, both captured.

### 6. The iOS asset set is generated and self-consistent — [structural]

Steps: a script/Dart check over `ios/Runner/Assets.xcassets/AppIcon.appiconset/`
that reads `Contents.json` and, for every entry, opens the named PNG and asserts
`width == height == size × scale`; plus a mode check that no PNG has an alpha
channel.

Expected: 15 files, every catalogue entry resolves, every PNG opaque. Proven by:
the check's output. **UNVERIFIED WITH REASON on the iOS half of SC-002**: no
macOS/Xcode on this host, so no simulator, no Xcode asset validation, no
store-icon preview — the same limitation spec 007 recorded.

### 7. Other platforms' icon sets are untouched — [structural]

Steps: `git status --short macos/ web/ windows/ linux/` and
`git diff --stat -- macos/ web/ windows/`.

Expected: empty. Proven by: git's own report (`data-model.md` I11, `research.md`
D7).

## Troubleshooting

**Nothing changed on the launcher after installing.** The launcher caches icons
per package; scenario 4's `pm clear` + reinstall is the deterministic path, and a
reboot also works. Check the APK first (scenario 1's hash) — if the packaged bytes
are right, it is caching.

**`InvalidConfigException: … adaptive …`.** Both `adaptive_icon_background` and
`adaptive_icon_foreground` must be set; `image_path` is **not** used as the
foreground implicitly (`contracts/icon-assets.md` §1).

**Icons are right but the build fails on a resource.** Check whether
`drawable-*/ic_launcher_background.png` was generated *and* `values/colors.xml`
was also written — both branches at once means the background value was switched
between a colour and a PNG without clearing the other (C4/C5).

**The subject looks cropped on Android 12+.** Confirm the inset line is still in
`mipmap-anydpi-v26/ic_launcher.xml` (`android:inset="16%"`); deleting it makes the
foreground full-bleed and the mask then eats ~8 % of the subject (C3).
